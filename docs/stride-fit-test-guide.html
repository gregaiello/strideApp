STRIDE on the treadmill: laps + .FIT test

From a factory-fresh console to a .fit on Strava. Build under test: your fork's main (laps, per-second recording, .fit export, "Strava elevation" on, optional switch button for a streaming app). Laptop commands are for Windows PowerShell. Tick each step off as you go; the ticks are remembered in this browser.

fills in the commands below (you read it in step 7)
Safety first. Clip the safety key to your clothing before the belt moves. To stop anything at any time: pull the safety key. If in doubt: switch the treadmill off at its power switch.
The factory reset is what makes this work. Start from a freshly reset console (step 3), not from whatever state the console is in today. The upstream README calls it out: the reset "has saved me more than once", and the install route was written for a just-reset machine. It is also your undo button: if any step goes wrong or the console gets stuck, factory reset and start again at step 3. Nothing you do here survives a reset, so it always gets you back to the original software.

2 Build the APK laptop

Part B · At the treadmill: factory reset, then from iFit to STRIDE
Already have STRIDE on the console, no iFit?
Use this short path instead of steps 3–11

Only take this path if that install is healthy. If it has ever acted oddly (iFit coming back, STRIDE not finding the board, a "which app?" prompt at boot), skip it and do the full path from the factory reset in step 3.

  1. Switch on, read the IP (Android Settings → About tablet), type it in the box at the top.
  2. & $adb connect CONSOLE-IP:5555, then & $adb devices shows it as device.
  3. From console\stride: & $adb -s CONSOLE-IP:5555 install -r app\build\outputs\apk\debug\app-debug.apk. If it fails with INSTALL_FAILED_UPDATE_INCOMPATIBLE, the installed STRIDE was signed with another key (e.g. the GitHub release). Nothing has changed. The only way past it is & $adb -s CONSOLE-IP:5555 uninstall dev.stride.hud and install again, and that wipes STRIDE's people, history and settings. Your call.
  4. Then continue at step 10.

3 Factory reset the console treadmill

Don't skip this. Every later step assumes a just-reset console. Leftover iFit state (a half-run earlier attempt, an update, iFit Admin's permissions) is the usual reason the later steps don't stick.

  1. Find the pinhole reset button: a single small hole on the side panel or the top of the console.
  2. Push a paperclip into the pinhole and hold it in while you switch the treadmill on at the power switch. The safety key isn't needed yet.
  3. Let go when System recovery appears in blue text.
  4. Let it finish. It takes 5–10 minutes. Don't switch off during it.
  5. The console boots into the iFit welcome screen, as it was out of the box.
✅ The iFit welcome / first-run screen, and the console isn't on Wi-Fi.
Don't join Wi-Fi. The reset forgets the network, so leave it forgotten. Stay offline until iFit is stopped in step 5, so it can't update itself or lock you out.
If iFit offers a software update, decline it. An update (Gen 7 / iFit 2.0) is reported to close the route used below.
If STRIDE was on the console before, the reset wipes it along with its people, history and settings. Copy anything you want to keep off the console first.
No System recovery screen, it just boots normally

The pinhole wasn't held in early enough. Switch off, hold the pinhole in before you flip the power switch, and keep holding until the blue text appears.

4 Enter privileged mode treadmill

On the iFit welcome screen:

  1. Tap a blank area of the screen 10 times.
  2. Wait 7 seconds. Nothing appears during the pause.
  3. Tap the same spot 10 more times.
  4. The console shows a challenge code. Get the matching response code: ring NordicTrack support and ask for one, or use a third-party calculator such as getresponsecode.com (not connected to STRIDE).
  5. Enter the response code.
✅ The console opens the plain Android apps screen. Tap Settings.
Nothing happens after the taps

Tap faster and in exactly the same spot, and make sure the pause really is about 7 seconds. Try a different blank area if the first doesn't work. If the console joined Wi-Fi or took an update, factory reset again (step 3) and stay offline this time.

5 Stop iFit locking you out treadmill

Do this before anything else. Skipping it undoes every later step at the next reboot. In Android Settings → Apps:

iFit Admin (com.ifit.eru). It's a system app and can't be uninstalled:

  1. Open it and tap Force stop.
  2. Settings → Apps → Special access → Display over other apps: set iFit Admin to Not allowed.
  3. Settings → Apps → Special access → Modify system settings: set iFit Admin to off.

iFit (com.ifit.standalone):

  1. Open it, tap Force stop, then Uninstall.
✅ iFit is gone from the app list and iFit Admin shows as stopped.

9 Run unchain: disable iFit for good, install STRIDE laptop · Git Bash

tools/unchain.sh does five things in order:

  1. disables iFit Admin, the part that re-locks the console at boot;
  2. disables the iFit launcher;
  3. keeps ADB and developer settings on;
  4. installs the STRIDE you built in step 2 and launches it;
  5. makes STRIDE the home app, so the console always comes back to it.

It's a bash script, so run it in Git Bash, not PowerShell (Start → "Git Bash"). Your checkout has Windows line endings, which bash can't run, so these commands run a converted copy and tidy up afterwards:

cd /c/path/to/strideApp
export PATH="$PATH:$(cygpath "$LOCALAPPDATA")/Android/Sdk/platform-tools"
sed 's/\r$//' tools/unchain.sh > tools/unchain-lf.sh
STRIDE_DEVICE=CONSOLE-IP:5555 bash tools/unchain-lf.sh
rm tools/unchain-lf.sh
mv tools/device-state.txt ../device-state.txt
✅ It ends with >>> DONE — eru disabled, STRIDE installed and set as home, and the console shows the STRIDE welcome screen.
Read what it prints. If it says it could not pin ADB over Wi-Fi, that's common and usually harmless: Wi-Fi ADB comes back after a power cycle on most consoles. Step 12 checks yours.
The last command moves device-state.txt (a snapshot of the console, for diagnosis) out of the repo so it never ends up in a commit.
It says No STRIDE APK yet

Step 2 didn't produce the APK. Build it (step 2), then run the commands again. Running it twice is safe.

It says INSTALL_FAILED_UPDATE_INCOMPATIBLE

A STRIDE signed with another key is already on the console. See the box at the top of Part B.

11 Set STRIDE up treadmill

On a fresh install nobody exists yet. On the console, in STRIDE's settings (its gear icon):

  • Who walks: add yourself. Guests are never recorded, so you need to walk as a named person.
  • Treadmill → Saved walks → Strava elevation: on (the default). This is what makes Strava keep the climb.
  • Interface: any of the five. Original is the most tested.
  • Home Assistant: optional; skip it for this test.
  • Display → Switch button (optional): tap USE next to your streaming app. Only video apps are listed (Netflix, Prime Video, NewPipe and a few others, if installed). A round button showing the app's icon appears at the right edge, over every app, and flips between STRIDE and that app. Drag it up or down to move it. If the section says STRIDE is not allowed to draw over other apps, tap ALLOW, or from the laptop: 
    & $adb -s CONSOLE-IP:5555 shell appops set dev.stride.hud SYSTEM_ALERT_WINDOW allow
  • Headphones (optional): put your Bluetooth headphones in pairing mode (not connected to your phone), tap SEARCH, then PAIR. When the line says Connected · sound plays here, every app's sound, the coach included, goes to them. They reconnect on their own next time. FORGET removes them for good.
  • Treadmill → Copy to NAS (optional): every .fit is also copied over SFTP to <home>/<your name>/ on the NAS. Fill in the NAS address (its IP or its network name, not a .local name), port (22) and user, tap CHECK.
    ✅ Found 192.168.… · SSH answers (…).
    Then type the NAS password and tap SET UP. The password is used once, to install STRIDE's own key, and is not kept.
    ✅ Ready, and a second CHECK ends in login and folder OK.
    On a Synology, first turn on SSH (Control Panel → Terminal & SNMP), SFTP (File Services) and the user home service (User & Group → Advanced).
  • My routes → From your NAS (optional, after the NAS is set up): STRIDE creates a routes folder next to your walk folders on the NAS. Put a .gpx with elevation in it (on Strava: an activity's ⋯ → Export GPX), then tap FETCH.
    ✅ 1 route(s) from /home/…/routes, and the route listed above with its profile, marked from the NAS.
    A file listed as skipped: no elevation in this file came from a planner that doesn't store heights; export the recorded activity instead.
  • About → Reset every setting needs the PIN 1235. Leave it alone for this test.
Install YouTube, Netflix and Prime Video (for the switch button)

The console has no Play Store, so everything is installed from the laptop. YouTube also needs Google Play services, which the console doesn't have either (without it YouTube says "your device does not support Google Play"), so Google's three parts go on first. These are the newest versions that run on the console's Android 9 (checked November 2026):

  • Google Services Framework 9-6957767: APKMirror. It must be a 9-… version, the one built for Android 9.
  • Google Play services 26.36.33, the arm64-v8a + armeabi-v7a, Android 9.0+, nodpi APK: APKMirror. A newer stable release (not one marked beta) with that same variant is fine.
  • Google Play Store 53.9.23, the universal, Android 7.0+ APK: APKMirror.
  • YouTube 21.23.485, the universal APK (not a BUNDLE): APKMirror. 21.23 is the last YouTube for Android 9; from 21.24 on it needs Android 10, so don't update past it.
  • Netflix 9.90.1 build 12 74817: APKMirror. Netflix still supports Android 9, so a newer stable release with Android 9.0+ in its variant list is fine too.
  • Prime Video 3.0.479, the arm64-v8a variant: APKMirror. Pick Amazon Prime Video (the phone app), not the Android TV or Fire TV ones.
  1. Download them into your Downloads folder and rename them gsf.apk, gms.apk, vending.apk, youtube.apk, netflix.apk and primevideo.apk.
  2. Optional, but it proves the files really come from Google, Netflix and Amazon. Check who signed them: 
    $apksigner = (Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\build-tools\*\apksigner.bat" | Select-Object -Last 1).FullName
foreach ($f in "gsf","gms","vending","youtube","netflix","primevideo") {
  "== $f"; & $apksigner verify --print-certs "$env:USERPROFILE\Downloads\$f.apk" | Select-String "SHA-256"
}
    ✅ gsf, gms, vending: f0fd6c5b410f25cb…2d60db83 (Google). youtube: one line ends …7c23f326c8f994a (starting 3d7a1223). netflix: one line ends …742390e682164e6b (starting 363863596ea9). primevideo: 2f19adeb284eb36f…ab6d7625 (Amazon Services LLC). Anything else: don't install it.
  3. Install, in this order: Google's three parts depend on each other. Plain adb install has failed silently on this console, so each file is copied over and installed on the console itself: 
    foreach ($f in "gsf","gms","vending","youtube","netflix","primevideo") {
  & $adb -s CONSOLE-IP:5555 push "$env:USERPROFILE\Downloads\$f.apk" /data/local/tmp/$f.apk
  & $adb -s CONSOLE-IP:5555 shell pm install -r /data/local/tmp/$f.apk
  & $adb -s CONSOLE-IP:5555 shell rm -f /data/local/tmp/$f.apk
}
    ✅ Success six times.
  4. Google's parts are installed as ordinary apps here, so they don't get the permissions they would have on a phone. Grant them: 
    foreach ($p in "com.google.android.gsf","com.google.android.gms","com.android.vending") {
  $perms = & $adb -s CONSOLE-IP:5555 shell dumpsys package $p |
    Select-String 'android\.permission\.[A-Z_]+' -AllMatches | ForEach-Object { $_.Matches.Value } | Sort-Object -Unique
  foreach ($x in $perms) { & $adb -s CONSOLE-IP:5555 shell pm grant $p $x 2>$null }
}
    Errors for permissions that can't be granted this way are normal and hidden.
  5. On the console, open YouTube: it should start, at its cookie choice. Signing in is optional, in YouTube or the Play Store. If Google refuses because the device isn't certified, the console has to be registered at google.com/android/uncertified.
  6. Pick an app under Display → Switch button.
What to expect: Netflix plays in SD, because this console is not Google-certified. Play services is big and the console has 2 GB of memory; uninstalling the three Google apps undoes all of it. The pushes take a few minutes over Wi-Fi (Play services about 280 MB, Netflix 280 MB, YouTube and Prime Video about 190 MB each). Rather not have Google on it? NewPipe plays YouTube without any of it, in its own plainer look.

iFit is back

Factory reset (step 3) and go through Part B again, staying offline until step 5 is done. Make sure step 9 runs to DONE. Patching it up from where it is (steps 4, 5, 9 only) can work, but a clean reset is the reliable route.

Part C · The test walk

13 Walk treadmill

Clip the safety key on now.
  1. Choose yourself and a workout. Walk at least 5 minutes. Anything under 300 m or 3 minutes is deliberately not saved.
  2. Add some incline with the physical buttons, so there is a climb to check later.
  3. Press LAP 2–3 times, a minute or more apart. Each press: the lap counter goes up, the lap time and distance restart, and you briefly see "Lap N done". In Cluster the lap has its own row under the totals: time, distance, average heart rate, climb and VAM (m/h, after the first 30 s).
  4. Pause once for about 30 seconds, then resume.
  5. Press the console's own STOP key (not the safety key): the belt stops, STRIDE shows its paused screen and the timer stops. The console's START key resumes the walk in STRIDE too.
  6. If you turned on the switch button: tap it to go to your streaming app, walk a minute there, tap it again to come back, and press LAP. The walk keeps counting the whole time, and the log shows no runaway.
  7. If you have a heart-rate strap, wear it.
  8. Cluster: the right-hand dial shows PACE MIN/KM; tap the number to switch to km/h and back. Both rings fill against your machine's own range (on the X22i, 22 km/h and +40 %), not 12 %.
  9. Optional, at about 2 km/h with a hand near the safety key: open Recents and swipe STRIDE away. The belt stops within about a second, and the log shows closing — belt told to stop. Start a new walk afterwards.
  10. Press END.
✅ On the summary: today's date, and an "N LAPS ›" pill (top right) that opens the lap table (tap anywhere to close it). Write down the summary's distance and climb.
✅ In the log: recording: saved …jsonl, then within a few seconds fit: wrote 2026-11-04_HHMM_<you>.fit.
The log says walk too short, discarded

Under 300 m or 3 minutes of moving time. Walk again, longer.

The log says fit: export failed …

Copy the whole message (it is followed by a stack trace) and include it in an issue. The walk itself is kept and the export is tried again the next time STRIDE starts.

14 Copy the .fit to the laptop laptop

Stop the log with Ctrl+C, then:

& $adb -s CONSOLE-IP:5555 shell ls -l /sdcard/Android/data/dev.stride.hud/files/fit/
mkdir $env:USERPROFILE\Documents\stride-fit -Force
& $adb -s CONSOLE-IP:5555 pull /sdcard/Android/data/dev.stride.hud/files/fit/ $env:USERPROFILE\Documents\stride-fit\
✅ A file named like 2026-11-04_0712_<you>.fit is now in Documents\stride-fit\fit\ in your user folder.

If you set up Copy to NAS, the same file is also in the folder named after you in the NAS account's home, with nothing to copy by hand.

15 Upload to Strava and check browser

  1. strava.com → + (top right) → Upload activity → File → pick the .fit.

Check, against the numbers from step 13:

  • Map: a small circle in the sea off Lerici, in Italian waters. Its place sets the time zone Strava shows the walk in, so date and time should match the console's.
  • Elevation gain: close to the summary's climb, not hundreds of metres.
  • Distance: matches the summary.
  • Moving time: excludes the ~30 s pause. Elapsed time: includes it.
  • Laps: your LAP presses appear as laps (Strava: the activity's Laps tab).
  • Heart rate: a graph if you wore a strap; no graph at all (not a flat zero line) if you didn't.
  • Date and start time: today, the time you started.
✅ All match: the test passed. If anything didn't, please open an issue saying what you saw.
The Strava upload is a real activity on your profile. Delete it afterwards if you don't want to keep it (activity → … → Delete).
